# pi-001 — Runtime auto-stop for tmux subagents

## Summary

Added an opt-in `autoStopOnComplete` launch parameter to `tmux_subagent` so callers can clean up disposable child sessions without changing the default lifecycle. Completed child sessions still stay alive unless the caller explicitly opts in.

## Implemented behavior

- Added `autoStopOnComplete?: boolean` to the tool schema and launch metadata.
- Foreground runs stop their tmux session after a clean completed status is observed and the result has been read.
- Background runs persist the preference and stop lazily when a later `status` call observes clean completion.
- Failed, stopped, starting, running, or otherwise non-completed sessions remain available for inspection.
- Auto-stop failures are best-effort: the result remains visible, the response includes an auto-stop warning, and the manual stop hint remains available.

## Documentation and tests

- Updated README usage examples and lifecycle wording.
- Updated `docs/STRUCTURE.md` lifecycle guidance.
- Added tests for schema exposure, persisted launch metadata, successful cleanup, cleanup failure handling, non-completed sessions staying alive, and formatting.
